# 变更记录

> 从 README 移出，保留原文。
## 变更

**0.11.2（整体性能审查）**
- **修**：同步检查在每个新标签页都先算全量配置哈希（canonical + SHA-256，
  配置含内嵌图标时几百 KB），哪怕远没到同步间隔。现在先判断「要不要同步」，
  命中 skip 时几乎零开销
- **修**：壁纸预览已覆盖视口时（最常见情况），不再读 IndexedDB + 解码
  2560px 原图——每个新标签页省一次 IDB 读和一次大图解码；大屏/高分屏
  超出预览分辨率时仍加载原图
- **改**：`boot.js` 提到样式表之前（不等 CSS 获取就能执行，打底色与壁纸
  缓存更早上屏）；新增 `<meta name="color-scheme">`，浏览器画布在最底层
  就跟随系统明暗，消除最深层的那一帧白底
- 实测（无头 + 真实扩展）：boot 打底 2.2ms 就位，主模块执行 + 首次渲染
  共 44ms，加载期零 JS 异常
- 审查确认无需改动：设置面板是打开时才构建（非启动时）、时钟农历按天缓存、
  心跳在页面隐藏时暂停、组件内部输入只落盘不触发重渲染

**0.11.1（打底色跟壁纸走）**
- **修**：浏览器深色主题 + 浅色壁纸时，首帧打底仍是深色——「深色帧 → 亮壁纸」本身就是一次闪
- 打底色优先级改为：**壁纸均色**（上传时顺手算好存起来）→ 壁纸明暗倾向 → 浏览器主题
- 自动配色的文字方向也多了一层兜底：正式采样结论 → 壁纸整体粗采样 → 主题默认
- 均色/倾向在生成壁纸首帧缓存时一并计算，不增加任何额外开销
- smoke 新增 4 项（深色系统 + 亮壁纸、无均色兜底、均色优先、预设仍跟主题）到 152 项

**0.11.0（首帧防闪）**
- **修**：新标签页明显闪屏。三个来源三个解法，参考了同类项目的公开经验
  （Beautiful Photos 的 data URL 本地缓存、PlainTab 的首帧同步缩略图、
  Chromium 论坛 wOxxOm 的「打底色与浏览器主题一致」）：
  1. **壁纸异步**（主因）：IndexedDB 在 `<head>` 里读不了，首帧只有纯色、
     图随后突然出现。现在上传/导入时把壁纸压成预览（最长边 1600px WebP，约 100-300KB）
     存进 localStorage，boot.js **同步**取出铺在 `<html>` 上——首帧就是壁纸本体；
     主流程异步加载的原图随后无缝覆盖。老用户升级后第一次打开自动补生成
  2. **CSS 加载前的白帧**：boot.js 按主题同步设置打底色（深 #16181c / 浅 #f4f3ef），
     与浏览器 UI 一致；图片壁纸时 `#bg`/`body` 的实色底放透明，让首帧壁纸透出来
  3. **自动配色翻转**：采样结论已有缓存（`zl.adapt`），boot.js 首帧前直接应用
     （校验 imageKey，换过壁纸不套用）
- smoke 新增 11 项：vm 沙箱跑 boot.js，断言打底色 / 壁纸缓存上屏 / 配色缓存套用 / key 不匹配不套用
- 页面预算 68 → 72 KB

**0.10.0（图标渲染重构 + 隐藏名称 + 白边修复）**
- **修**：网易云那类「白方块 + 红圆」favicon 的白底去不掉。两个根因：
  1. 白方块四周有**透明边距**，旧版从画布字面边缘找白，被边距挡住直接放弃——
     泛洪改为可穿透透明像素传播，贴边白清得更干净
  2. `OffscreenCanvas.convertToBlob` 返回 Promise，没 await 就把 Blob 对象当 URL 赋给 img.src，
     得到一张坏图（`[object Blob]`）
- **新增**：右键 → 「隐藏名称 / 显示名称」。只隐藏图标底下的文字，图标本身保留，
  且名称不再占位后图标自动长大一档（`hideName` 存在 item 上，同步导出都跟随）
- **重构**：图标渲染拆成独立组件 `iconview.js`（来源分流 + 统一缓存 + 处理编排），
  `favicon.js` 瘦身为纯数据源；像素判定集中在纯函数 `iconproc.js`
- 性能：处理结果统一缓存（src+模式 为键，含「放弃」结果，重渲染零重复计算）；
  Firefox 图标缓存一次 `idbAll` 批量读（原来逐个 await）；有 `createImageBitmap` 时
  解码走离屏位图；同一张图并发请求合并为一次处理
- smoke 补白边闸门测试到 135 项

**0.9.0（自定义图标）**
- **新增**：右键链接 → 「自定义图标…」上传本地图片，支持 PNG/JPEG/WebP/GIF/SVG/ICO/BMP（≤2MB）
- 格式识别靠魔数优先、扩展名兜底；SVG 保留原文不栅格化，位图上传时降到 192px 转 PNG（保住透明，也控制体积）
- **同步**：WebDAV 带自定义图标（内嵌在配置里），GitHub 不带；GitHub 拉取时本地图标按 id 保留
- 手动导出自然包含（图标就在配置里）；图标变更会改变内容哈希，触发一次同步
- **新增**：「透明图标去白边」开关（默认关）——从四条边泛洪填充，只清与边缘连通的近白像素，
  logo 内部的白色不受影响；裁完剩不到 8% 不透明就放弃。开关即时生效，不用重新上传
- 右键菜单区分「更换图标…」「恢复默认图标」；操作反馈用轻提示
- 新模块 `iconproc.js`（格式嗅探/透明检测/白边裁切，纯函数），smoke 补 24 项到 131
- 页面预算 60 → 68 KB

**0.8.2（去白底失效）**
- **修**：开了「去掉图标白底」没反应。两个原因叠在一起：
  1. 判定用的是「四角都是白」，而白色圆角方块的四角是**透明的**（圆角外面），直接被判成「没有底板」放过
  2. 就算抠掉了 favicon 的白底，图标容器自己还有一层 `--card` 白底，视觉上看不出变化
- 判定改成取四条边的**中段**（避开圆角）算白色占比，≥70% 才处理
- 抠底成功后给容器加 `.stripped`：底色、边框、阴影去掉，内边距从 13% 收到 2%，图标真正浮在壁纸上
- 「主体也是白」的闸门从 82% 提到 96%

**0.8.1（图标尺寸曲线）**
- **修**：大格子里图标偏小，2×2 只有 88px、4×3 也只有 122px，四周空得像个房间
- 图标尺寸改成按格子的**实际像素**算（短边 60%），而不是按行数加常数
- 填充率：2×2 从 31% → 36%，4×3 从 27% → 44%（宽度）/60%（高度）
- 名称字号分四档（13/14/15.5/17px），大图标下名称与图标的间距同步放大

**0.8.0（任意尺寸 + 纯图标 + 隐藏）**

- **新增**：去掉图标自带白底。读 48×48 像素，四角接近纯白才处理，抠掉接近纯白的像素；主体本身是白（抠掉超过 82%）就放弃，深色图标不动。设置里可以关

**0.7.0（自由布局 + 412 自愈）**
- **改**：布局从「自动流」改成「显式坐标」。拖到哪格就停在哪，不再被网格重新排序
- 位置按 8 列基准存 `(col, row)`；窄屏换算后撞上时，撞的那个顺延，其他元素不动
- 拖动时显示虚线落点框；新增组件落在现有内容下方
- **修**：同步报「远端已被别处修改」时直接失败。412 意味着 etag 过期，可能只是另一个标签页刚推过。现在会回拉一次比对内容：一致就用新 etag 记下，真的不同才转成冲突让你选
- 「用本地覆盖远端」遇到 412 会重新取 etag 再推一次，不再拦人
- 新增 `test/layout.mjs`（7 项）：拖放落点、越界顺延、刷新后位置不变、窄屏不越界、新增落在末尾
- 内容比对抽成纯函数 `sameContent()`，补 3 项单测
- 页面预算 56 → 60 KB

**0.6.1（浮层可读性 + 采样缓存 + 遮罩收敛）**
- **修**：跟随系统 + 亮壁纸时，设置面板和组件选择器几乎不可读。根因是浮层用 `var(--bg)` 做底（仍按系统深色），文字却被自动配色改成了深色
- 浮层改成自己的一套配色 + 实色底，跟着页面当前明暗走（页面深色字 → 浅底浮层），不再出现深底深字
- **修**：35% 的白遮罩在亮壁纸上像蒙了一层雾。自动配色生效时遮罩降到 **15%**——配色已经解决可读性，遮罩只用来提亮/压暗局部
- 遮罩强度改成三套分开记：预设 `dim` / 照片+手动主题 `imageDim`（35%）/ 照片+跟随系统 `adaptDim`（15%），互不覆盖
- **新增**采样结果缓存（`zl.adapt`，指纹 = imageKey + 字节数 + 类型），二次打开不再解码壁纸
- 壁纸预设的色块预览也跟着自动配色翻面（之前页面是浅色，色块却全列深色版）
- 页面预算 52 → 56 KB

**0.6.0（布局上移 + 按壁纸自动配色）**
- **改**：布局从居中改成从上往下排，时间贴到顶部。居中的时间正好落在人像壁纸的头部，那里通常最暗也最花；极简模式仍然居中
- **新增**：跟随系统主题时按壁纸自动配色。把壁纸画进 16×16 canvas，只采样内容实际压着的那块（`cover` 坐标映射），算平均亮度后取「黑字」和「白字」里对比度更大的那个
- 自动配色时卡片比手动模式更透（深色 52% / 浅色 58%），可读性交给对比度而不是厚底色
- 重算只在三种时机发生：换壁纸、内容区变化（拖组件 / 改尺寸 / 窗口缩放）、页面打开；用 `MutationObserver` 观察网格，不做轮询
- 手动选浅色或深色主题时不生效，用户的选择优先
- 图片壁纸默认遮罩 50% → **35%**（配色已经对上，不需要那么重的遮罩压平照片）
- 选色逻辑抽成纯函数 `pickTone()`，补 8 项单测

**0.5.1（壁纸可读性）**
- **修**：照片壁纸下文字读不清。深色主题的白字压在亮天空上只有 1.17:1，浅色主题的黑字压在头发暗部只有 1.04:1

- 新增图片壁纸保底：卡片底色变实（深色 7% → 74%、浅色 66% → 84%）、时钟与图标名加双层文字阴影（黑白各一层）、次要文字从半透明提到实色
- 遮罩强度照片与预设分开记（`imageDim` / `dim`），照片默认 50%，切回预设不会把 50% 带过去；旧数据自动补默认值
- 新增 `test/vision.mjs`：构造极端壁纸（右上刺白、左下压黑），真实渲染后采样算 WCAG 对比度，7 项断言
- 页面预算 48 → 52 KB（CSS 增加约 1.2 KB）

**0.4.4**

**0.4.3**

- 所有 HTTP 错误都会带上服务器返回的一小段内容（WebDAV 通常返回 XML 说明），不再只有状态码

**0.4.2**
