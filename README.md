# Zenith 起始页

零遥测、最小权限的本地新标签页扩展。Chrome / Edge / Firefox 三端一套源码。

页面代码里没有任何网络请求；唯一会出网的是同步，默认关闭，开启后只连你自己填的服务器。

## 直接试用

**Chrome / Edge**

1. 打开 `chrome://extensions`（Edge 是 `edge://extensions`）
2. 打开右上角「开发者模式」
3. 点「加载已解压的扩展程序」，选 `dist/chrome`
4. 新开一个标签页即可

**Firefox**

1. 打开 `about:debugging#/runtime/this-firefox`
2. 点「临时载入附加组件」，选 `dist/firefox/manifest.json`
3. 图标默认是字母色块。页面底部会出现「启用网站图标」按钮，点它并授权 `tabs`，扩展会立刻扫描已打开的标签页并缓存图标；也可以在设置里再做一次

> Firefox 没有 `_favicon` 接口，只能从**已打开的标签页**读 `favIconUrl`（data: 内联数据，仍不发网络请求）。没访问过的站点暂时只有字母色块，访问一次后切回新标签页就会自动补上。
>
> Firefox 的临时扩展在重启后消失，这是浏览器的限制，不是扩展的问题。

## 布局

**从上往下排**：时间贴在最上方，然后依次是搜索框、组件、图标。不居中的原因是居中的时间正好落在人像壁纸的头部——那里往往是最暗或最花的一块，白字压上去就没了。极简模式仍然居中（只剩一行字贴顶会显得很怪）。

图标和小组件在**同一个网格**里，可以拖到任意格子。

- 宽屏 8 列、窄屏（<760px）4 列，行高 104px，列宽随字号缩放
- 图标占 1 格（图标在上、名称在下）或 2 格（图标在左、名称在右）
- 组件占 2/4 格宽、1/2 行高，尺寸由右上角按钮循环
- **位置是记下来的**：拖到第 7 列第 3 行就停在那儿，不会被自动流重新排序
- 拖动时贴着目标格显示虚线落点，松手前就知道会放哪

位置按 8 列基准存成 `(col, row)`。窗口变窄或组件改大后，如果换算过去撞上了，撞的那个顺延到下一个空位——不是整体重排，其他元素不动。

新增的组件会落在现有内容的下面，不会钻进第一行的空隙里。

默认布局：第一行「待办 4 格 + 纪念日 2 格 + 番茄钟 2 格」，第二行 8 个图标正好铺满。

## 小组件

8 个，全部本地计算，无任何接口依赖：

| 组件 | 说明 |
|---|---|
| 待办 | 回车添加，点勾完成，悬停删除 |
| 纪念日 | 点卡片设置名称与日期，显示已过/还有多少天 |
| 月历 | 当月网格 + 今天高亮 + 今日农历，可翻月 |
| 番茄钟 | 25 分钟，用结束时间戳计时，切走再回来不会走偏 |
| 便签 | 输入即存（防抖 400ms） |
| 计算器 | 手写递归下降解析，不用 `eval`，支持括号与小数 |
| 大写金额 | 1234.56 → 壹仟贰佰叁拾肆元伍角陆分 |
| 单位换算 | 长度 / 重量 / 温度 |

卡片布局用 CSS Grid 的跨列跨行实现，不做自由像素定位——好处是永远对齐、不会重叠、缩放字号后也不会错位。

## 显示开关

设置 → 显示，三项都可以关：

| 开关 | 作用 |
|---|---|
| 搜索栏 | 隐藏搜索框（`/` 快捷键也会一起失效） |
| 添加组件按钮 | 隐藏网格右下角的入口 |
| 极简模式 | 只留时间，其余全部隐藏；点首页时间或按 `Esc` 可随时退出 |

## 图标与尺寸

**尺寸**：任意元素都可以是 1–4 列 × 1–3 行的组合（1×1、2×1、1×2、2×2、2×3、3×3、4×2……）。
点右上角的尺寸按钮弹出格子矩阵，悬停预览要占的矩形，点一下定档——不用循环点十几次。

上限是 4 列（半行）和 3 行（312px）。再大就超出一屏，翻页才能看全，反而不好用。

**图标会跟着尺寸长**：

尺寸按**格子的实际像素**算：占短边的 60%，再被「高度减去名称」卡一道。不是按行数加常数——那样 4×3 会像一间空房间。

| 尺寸 | 格子 | 图标边长 | 布局 |
|---|---|---|---|
| 1×1 | 105×104 | 60px | 图标上、名称下 |
| 2×1 / 4×1 | 221×104 | 64px | 图标左、名称右（横排） |
| 1×2 | 105×220 | 63px | 图标上、名称下 |
| 2×2 | 221×220 | 132px | 名称字号提一档 |
| 2×3 | 221×328 | 133px | 同上 |
| 3×3 / 4×3 | 338×336 | 202px | 同上 |

名称字号和图标间距也跟着分级：图标越大，名称越大、离得越远。

**纯图标**：有些站点给的 favicon 是「白色圆角底 + logo」，叠在浅色卡片上像套了两层底。
开启「设置 → 图标 → 去掉图标白底」后，扩展把图标画进 canvas 读像素，
从四条边做**泛洪填充**——可以穿过透明像素传播（很多 favicon 的白方块四周留了透明边距，
只看字面边缘会什么都找不到），把与边缘连通的近白像素清成透明；
logo 内部的白色（图标里的白字）被有色区域包着，不会被动到。
抠掉底板的同时，图标容器那层底也一起去掉——否则只是把「两层白底」变成「一层白底」。

四道闸门防止误伤：内容没填满包围盒（细笔画 logo）不处理；裁完接近全白（主体本身是白）放弃；
裁完只剩不到 8% 不透明（白色字母标贴边）放弃；处理在像素副本上做，
任何一道闸没过，原图字节分毫不动。

**隐藏**：右键图标选「隐藏」，它从首页消失但保留在数据里，设置 → 图标 里能看到并一键恢复。
和「移除」分开——移除了就得重新加回来。

**自定义图标**：右键链接 → 「自定义图标…」上传本地图片（PNG/JPEG/WebP/GIF/SVG/ICO/BMP，≤2MB），
「更换图标…」替换，「恢复默认图标」还原。格式识别靠魔数优先、扩展名兜底——文件 type 为空也能认出来。

- **SVG** 保留原文不做栅格化，缩放交给浏览器，多大尺寸都清晰
- **位图** 上传时统一降到最长边 192px 转成 PNG：保住透明通道，也把体积压到几十 KB，
  不至于把 localStorage 和同步配置撑爆；动态 GIF 取第一帧
- 上传的图标存在配置里（`item.icon` 数据 URL），**WebDAV 同步和手动导出都会带上，GitHub 同步不带**
  ——配置文件里嵌 base64 会让仓库 diff 很难看。GitHub 拉取时本地已有图标按 id 保留，不会被抹掉
- **透明图标去白边**（设置 → 图标，默认关）：开了以后，上传的透明图标会把
  **贴着边缘的白色区域**清掉——从四条边泛洪填充，只清与边缘连通的近白像素，
  logo 内部的白色（比如图标里的白字）不与边缘连通，不会被动到。
  裁完只剩不到 8% 不透明（说明主体贴边是白的）就放弃。开关即时生效，不用重新上传

## 壁纸可读性

预设渐变是均匀的，照片不是：同一屏上可能一处刺白、一处发黑。旧版只有一个「压暗」滑块——深色主题靠它能把白字从亮天空里救出来，浅色主题却越压越糟，黑字本来就压在照片的暗部。

现在三件事一起做：

**1. 双向遮罩，跟主题联动**

遮罩颜色由主题决定：深色主题用黑（压暗亮壁纸），浅色主题用白（提亮暗壁纸）。用户只调强度。

形状是**中心浓、边缘淡的径向渐变**，不是均匀铺满——内容都在中间，四角留给壁纸本身，照片不会被压成一片平灰。

强度默认：照片 **50%**、预设 **0%**。两套值分开记在 `wallpaper.imageDim` 和 `wallpaper.dim` 里，从照片切回预设时不会把 50% 带过去。

**2. 图片壁纸时卡片变实**

深色主题的卡片原本是 7% 白，在深色渐变上还行，压在照片上等于没有底色。图片壁纸时切成 74% 深色；浅色主题从 66% 白提到 84% 白。

**3. 文字保底**

时钟、日期、图标名加双层阴影——黑的一层把浅色文字从亮背景剥开，白的一层把深色文字从暗背景剥开，**一套值同时适配两种主题**（单色阴影只能救一半）。图标名从 55% 透明提到实色，右下角的「设置」「添加组件」也提一档。

实测对比（构造的极端壁纸：右上刺白、左下压黑，比真实照片更严格）：

| 位置 | 修复前 | 修复后 | 参考线 |
|---|---|---|---|
| 深色 · 时钟压亮处 | 1.17 | **3.38** | 大字号 AA 3.0 |
| 深色 · 图标名压天空 | 1.64 | **5.55** | 正文 AA 4.5 |
| 深色 · 卡片内文字 | 1.17 | **10.65** | 正文 AA 4.5 |
| 浅色 · 图标名压暗部 | 1.04 | **5.05** | 正文 AA 4.5 |

50% 这个默认值就是按「最坏位置也过线」定的，觉得太重可以拉到 30%。

**代价说清楚**：浅色主题 + 照片会偏白，深色主题 + 照片会偏灰。均匀遮罩能做到同样可读性，但整张照片会一起变平；渐变版在内容区强度相同、边缘只留一半，观感损失小一些。

**没做的两件事**

- **`backdrop-filter` 毛玻璃**：卡片会更好看，但每帧都要对背后区域做模糊，拖拽和滚动时有掉帧风险。这套 UI 的卖点是轻，不值当。
- **自动判断壁纸明暗切主题**：用 canvas 采样就能实现，但用户手动选了深色主题，替他改掉会很意外。既然遮罩让两种主题都能用，就不抢先替他决定。

性能：遮罩是静态合成层，没有新增每帧计算，也没有新增 JS 分支。CSS 增加约 1.2 KB（gzip），页面预算从 48 KB 调到 52 KB。

### 按壁纸自动配色

「跟随系统」主题下，文字颜色本来跟壁纸无关——系统是深色就一直白字，壁纸一亮就白压白。现在会采样壁纸：

1. 把壁纸画进 16×16 的 canvas，只取**内容实际压着的那块**（背景是 `cover`，要把屏幕矩形映射回图片坐标）
2. 算这块的平均相对亮度 L
3. 分别算黑字、白字跟这个亮度的对比度，取大的那个

亮壁纸自动用深色文字，暗壁纸自动用浅色文字，卡片底色跟着翻到相反方向，而且比手动模式更透——可读性交给对比度，不靠厚底色硬压。

**重算时机只有三处**：换了壁纸、内容区变了（拖组件 / 改尺寸 / 窗口缩放）、页面打开。平时不算，结果是静态的，不需要每帧。

手动选了浅色或深色主题时**不生效**，用户的选择优先于自动推断。

采样用的是本机 blob，同源、不联网，读完就在内存里丢掉。

**结果会缓存**：算出来的结论存进 `localStorage` 的 `zl.adapt`，指纹是「imageKey + 字节数 + 类型」。下次打开同一张壁纸直接读缓存，不用再解码整张图；只有换了壁纸或改了布局才重算。布局变化时如果解码结果还在内存里，就按新区域重采一次（约 1ms），不重复解码。

**浮层不跟着翻**。设置面板和组件选择器是实色底，配色只跟真实主题（系统或手动）走，不跟壁纸自动配色翻——否则壁纸一亮，全局文字变深色，而面板底还是深色，整块标题会消失。这是 0.6.1 修的问题。

## 同步

设置 → 同步，三选一：**关闭 / WebDAV / GitHub**。默认关闭，关闭状态下扩展一个网络请求都不发。

**WebDAV**（坚果云、Nextcloud、群晖、Alist 都行）

| 字段 | 说明 |
|---|---|
| 服务器地址 | 例如 `https://dav.jianguoyun.com/dav/` |
| 用户名 / 应用密码 | 坚果云要在「安全选项」里生成应用密码，不能直接用登录密码 |
| 文件路径 | 默认 `zenith/config.json`，**目录不存在会自动逐级创建**（`zenith` 或其上级都行） |

> **第一次点按钮会弹一次授权框**，问你是否允许扩展访问这个域名。必须点允许，否则之后所有请求都会报 `Failed to fetch`。
> 授权是**按域名**的，换服务器地址要重新授权一次。
> 如果点了没反应：`permissions.request` 必须在点击的同一个任务里调用，先做任何异步操作都会让手势失效——这是实现上最容易踩的坑，代码里已经按这个顺序写死。
>
> **服务器对不存在的路径返回 409 怎么办**：群晖等服务器会出现这种情况。扩展会先发一次 `PROPFIND` 判断这个路径是文件、目录还是不存在——不存在就当作「还没同步过」照常上传；如果路径其实是个文件夹，会直接提示你把文件路径改成 `zenith/config.json` 这种指向文件的形式。

### 目录自动创建

WebDAV 的 `MKCOL` 一次只能建一层，所以同步时会从你填的地址开始**逐级往下建**。例如路径填 `zenith/sub/config.json`，会依次对 `zenith`、`zenith/sub` 发 `MKCOL`，已存在的层级（405/409）自动跳过，最后才 `PUT` 文件。

上传结果里会写明建了几层；如果目录被人删过，下次上传遇到 409 会自动补建并重试一次。

**GitHub**（只传配置；自定义图标不同步——嵌 base64 会让仓库 diff 很难看）

| 字段 | 说明 |
|---|---|
| 仓库 | `owner/repo` |
| PAT | 细粒度令牌，只需该仓库的 Contents 读写 |
| 分支 / 路径 | 默认 `main` / `zenith/config.json` |

> GitHub 走 `api.github.com`，同样需要一次授权。
> 拉取时本地已上传的自定义图标按 id 保留，不会被抹掉；要转移图标用 WebDAV 同步或手动导出。

**WebDAV** 则会把自定义图标（base64 内嵌在配置里）一起同步，换设备后图标直接回来。

> **Firefox 需要 128 或更高版本**才能按需申请域名权限（`optional_host_permissions` 从 128 开始支持）。低版本可以正常用其它功能，但同步无法授权。

### 同步规则

- 默认 **24 小时对比一次**，可改，下限 **15 分钟**（避免触发服务端限流）
- 打开新标签页时才检查，浏览器关着的时候不同步——本来也不需要
- 比的是内容哈希和远端 ETag/sha，**两边都没变就不发请求体**
- 只有一边变了：本地变就上传，远端变就拉取
- **两边都变了**：不自动合并，设置里会出现「用远端覆盖本地 / 用本地覆盖远端」两个按钮

同步只包含布局、图标地址、组件数据；壁纸图片和图标缓存不进同步，靠下面的导入导出搬。

## 导入导出

设置 → 数据：

- **导出配置**：生成单个 JSON，含布局、壁纸图片（base64）和图标缓存（最多 800 个），换机器直接恢复
- **导入配置**：选文件即可，导入后自动刷新

不做 zip 是为了少一个依赖，代价是体积大约多 1/3。

```bash
node test/serve.mjs 8787 # 静态服务器预览（会带上 CSP 头）

```

端到端检查（需要真实扩展环境，能验证后台是否真的起来了）：


Node 18+，无第三方依赖，没有 `node_modules`。

### 可复现构建

- 不引入任何构建期依赖，构建只做「复制 + 生成 manifest + 固定 mtime」
- 同一份源码任何时候构建出的字节流一致，产物内的 `BUILD.txt` 带源码指纹
- zip / xpi 也用内置打包器生成（`tools/zip.mjs`，固定时间戳），两次打包 sha256 相同
- 想升级依赖时不必担心锁文件漂移——本来就没有

## 设计约束（不要破坏）

| 约束 | 落地方式 | 守卫 |
|---|---|---|
| 页面不联网 | **页面代码里没有任何网络 API**；构建期扫描强制（CSP 的 `connect-src` 不能写 `'none'`，见下方说明） | 构建脚本扫描，页面侧命中即失败 |
| 出网只有一个出口 | 只有 `sync-core.js` 里的 `fetch` 会真正发出请求，且只发往用户填的那一个地址；同步关闭时零请求 | 白名单扫描，其余文件出现网络 API 即构建失败 |
| 不执行远程/动态代码 | CSP `script-src 'self'`；全树禁止 `eval`/`new Function` | 同上 |
| 零遥测 | 无任何统计、上报、崩溃收集代码 | 源码审查 |
| 最小权限 | 静态权限只有 `unlimitedStorage`/`storage`/`favicon`；主机权限全部是**可选**，用哪个域名才申请哪个 | 构建脚本校验 |
| 首屏快 | 壁纸用 CSS 变量、首帧同步读 localStorage、组件零框架；壁纸采样的结论会缓存，二次打开不再解码 | 页面 gzip ≤56 KB、后台 ≤16 KB，构建时校验 |
| 照片上也读得清 | 双向渐变遮罩 + 实卡片 + 双层文字阴影 + 跟随系统时按壁纸自动配色 | `test/vision.mjs` 采样算对比度 |

> **为什么 `connect-src` 不是 `'none'`**：MV3 的 `content_security_policy.extension_pages` 同时作用于 service worker。早期版本写了 `connect-src 'none'`，结果后台的 `fetch` 被自己的 CSP 拦死，所有同步请求都返回 `Failed to fetch`，且与域名权限无关。
>
> 现在 `connect-src https: http:` 给后台放行，页面侧的「不联网」改由构建期扫描保证——除 `sync-core.js` 外任何文件出现 `fetch`/`XHR`/`WebSocket`/`sendBeacon` 都会让构建失败。这是浏览器强制换成了构建强制，比原来弱一档，但用 `test/e2e.mjs` 与产物扫描双保险补上。

权限对照：

| 权限 | 何时申请 | 用途 |
|---|---|---|
| `unlimitedStorage` | 安装时 | 存壁纸与图标缓存 |
| `storage` | 安装时 | 存同步配置与「上次同步状态」 |
| `favicon`（仅 Chromium） | 安装时 | `_favicon` 接口读本地图标缓存 |
| `bookmarks` | 点「从书签导入」时 | 一次性读取书签 |
| `tabs`（仅 Firefox） | 点「启用自动图标捕获」时 | 读 `favIconUrl` 拿 data: 图标 |
| `https://你的服务器/*` | 点「保存并授权」时 | 只覆盖你填的那一个域名 |

拒绝任何可选权限都不影响基本使用——同步和图标会退化，其余照常。

## 已知限制

- Firefox 的图标覆盖率取决于「标签页开着没有」，未访问站点是字母色块
- 网页图标只能二选一：要么来自浏览器缓存（Chromium `_favicon`），要么来自打开的标签页（Firefox）
- 壁纸首帧走 localStorage 里的压缩预览（最长边 1600px、WebP），原图（IndexedDB）异步覆盖；
  极高分辨率屏上头一两帧的锐度略低于原图，肉眼难辨
- 同步不合并冲突：两边都改过时只能整体覆盖，没有字段级合并
- Chrome 的 `favicon` 权限在极旧版本（<104）不可用，manifest 已声明 `minimum_chrome_version`

## 变更

**0.11.2（整体性能审查）**
- **修**：同步检查在每个新标签页都先算全量配置哈希（canonical + SHA-256，
  配置含内嵌图标时几百 KB），哪怕远没到同步间隔。现在先判断「要不要同步」，
  命中 skip 时几乎零开销
- **修**：壁纸预览已覆盖视口时（最常见情况），不再读 IndexedDB + 解码
  2560px 原图——每个新标签页省一次 IDB 读和一次大图解码；大屏/高分屏
  超出预览分辨率时仍加载原图
- **改**：`boot.js` 提到样式表之前（不等 CSS 获取就能执行，打底色与壁纸
  缓存更早上屏）；新增 `<meta name="color-scheme">`，浏览器画布在最底层
  就跟随系统明暗，消除最深层的那一帧白底
- 实测（无头 + 真实扩展）：boot 打底 2.2ms 就位，主模块执行 + 首次渲染
  共 44ms，加载期零 JS 异常
- 审查确认无需改动：设置面板是打开时才构建（非启动时）、时钟农历按天缓存、
  心跳在页面隐藏时暂停、组件内部输入只落盘不触发重渲染

**0.11.0（首帧防闪）**
- **修**：新标签页明显闪屏。三个来源三个解法，参考了同类项目的公开经验
  （Beautiful Photos 的 data URL 本地缓存、PlainTab 的首帧同步缩略图、
  Chromium 论坛 wOxxOm 的「打底色与浏览器主题一致」）：
  1. **壁纸异步**（主因）：IndexedDB 在 `<head>` 里读不了，首帧只有纯色、

  3. **自动配色翻转**：采样结论已有缓存（`zl.adapt`），boot.js 首帧前直接应用
